# pyoxynet: Claude briefing

The open-source package behind the Oxynet papers: two frozen research models, a CNN and an LSTM,
run with LiteRT, so no TensorFlow is needed to use them. Package source is `pyoxynet/pyoxynet/`
(`pyoxynet/pyproject.toml`); the docs are on ReadTheDocs (`docs/`, Furo); tests run on Linux,
Windows and macOS (`.github/workflows/tests.yml`).

## The workspace: one of the Oxynet repositories

pyoxynet is one of the repositories that the Oxynet orchestration repo (`oxynet-cpet/oxynet`)
keeps aligned. Set up from there (`python3 harness/repos.py clone`), this repo sits at
`pyoxynet/` beneath it, and the workspace's own CLAUDE.md loads alongside this one: it holds
the rules shared by every repo and the release checklist that a pyoxynet tag follows too.

No code crosses: pyoxynet imports nothing from the other repos, and none of them imports it.
What ties it to them is shared files and statements:

| What | Where it lives | Rule |
|---|---|---|
| `docs/oxynet_brand.py`, `docs/_static/oxynet-mark.svg` | Generated by the workspace's `python3 harness/registry.py sync` from its brand registry | Never edit them here. Change the source there, `sync`, then `check` before committing |
| pyoxynet's version, Python range and licence | The website (`pyoxynet-website`, `PYOXYNET` in `src/content/developers/meta.ts`), shown on its Python and downloads pages | Follows a release only once PyPI has it |
| What the package is | The website's developer pages and its `/llms.txt` | A separate research package, not a client for the hosted API |
| The hosted Oxynet API | `app.oxynet.net`, its own repository | pyoxynet points at it and never describes it as part of the package |

A change that also touches the website is one PR here and one there, each merged on its own.

## Rules

- **The models are frozen.** They are never retrained or replaced in place: a different model
  is a new file and a new major version (`pyoxynet/pyoxynet/models/README.md` records where
  each file came from and its checksum).
- **Nothing flows in from the hosted service:** no production weights, parser, parser fixes
  or analyses. Polishing pyoxynet means making its own code install and run, not making it
  more like the service.
- **Citations come from Crossref, PubMed or this repository's docs**, never from memory.
- **Words:** no em dashes in anything a user reads; never a confidence percentage; oscillatory
  ventilation, wherever it is mentioned, is beta (one heart-failure cohort, transportability
  untested).

## Releasing

Check alignment before tagging, not after (maintainer, 2026-11-20).

1. **List what the release changes and every place that states it**, and read each against the
   code that will ship: `README.md`, `pyoxynet/README.md` (the PyPI page), `docs/*.rst`, and the
   website's `PYOXYNET` facts and Python page. Read every statement about the hosted API
   against what it serves today (`https://app.oxynet.net/llms-full.txt`). Check the citations.
   In the workspace, `python3 harness/registry.py check` must pass.
2. **Bump `version` in `pyoxynet/pyproject.toml`.** `master` needs an approving review, so the
   maintainer merges and pushes the `v*` tag. `.github/workflows/release.yml` refuses a tag that
   differs from that version, tests the wheel on all three systems, and publishes to PyPI by
   trusted publishing (publisher `oxynet-cpet/pyoxynet`, `release.yml`, environment `pypi`).
3. **Once PyPI shows the release:** a website PR moves `PYOXYNET` to it, and the ReadTheDocs
   build of `master` should show the new version.
4. **Keep it proportionate:** fix what is false; minor wording drift is noted once and left.
